# Plan: Cut the always-on text and the tutorial skills (cli#679, the cut half)

**Branch**: `044-always-on-cut` | **Date**: 2026-10-30 | **Backlog item**:
[specnaut-cli#679 — Slim the bundled skills and always-on text; enforce must-hold rules with hooks](https://github.com/specnaut/specnaut-cli/issues/679),
child of epic #674. The enforce half landed in spec 036; this is the cut half that waited on an
eval. The eval was dropped (Kevin, 2026-10-29): cuts land on a green suite, no content guard
weakened, bytes reported before and after — always-on bytes for both harnesses.

**Full plan** — the change deletes files in users' projects on upgrade (step 4b: files written or
deleted in someone else's project). It reuses the lock-driven orphan path, as cli#678 did.

## 1. Why this exists

Always-on context in a scaffolded project: `templates/core/root/AGENTS.md` is 12,972 B, of which the
`Optional integrations` tour (~75 lines, reference, tells the agent nothing to do) and the chain
section's five-row excuse catalogue (written for weaker models) are the bulk. It also pins a harness
version ("Requires Claude Code v2.1.139+", § VIII) and places "Generated by Specnaut. Edit freely."
mid-file, above six managed sections. `/task backlog.md` (17,690 B), `groom.md` (12,844 B) and
`/ship` (6,009 + 10,227 + 2,681 B) carry tutorial prose around their command tables. `alias-example`
is not installed and nothing reads `alias_of`; `claude-security-guidance.md` and
`security-patterns.yaml` are read by nothing (spec 036 decided: remove). `status-audit` asks the
model to derive seven views from JSONL by hand.

## 2. User scenarios

### US1 — a session starts in a scaffolded project (P1)

**Given** a project scaffolded or upgraded with this bundle **When** a Claude Code or Codex session
starts **Then** the always-on `AGENTS.md` carries the rules — constitution pointer first, the two
stops, invoke the next phase yourself, only CRITICAL/HIGH buys a cycle, the `merge: manual` hook —
and one pointer line to where the optional integrations are documented.

### US2 — the user asks for a session health report (P2)

**Given** `.specnaut/logs/agents.jsonl` **When** the user runs `/status-audit` **Then** a bundled
`jq` script computes the seven views and the skill presents them; the same on Codex (the ledger is
registered there since spec 036).

### US3 — a project upgrades (P1)

**Given** a project scaffolded with `alias-example` and the two security-guidance files **When**
`specnaut upgrade` runs **Then** they are removed through the orphan path, a customised one kept and
warned until `--force`; the trimmed managed sections replace the old ones.

### Edge cases

- A ledger line that is not JSON: skipped and counted, as today.
- `jq` absent: the script says so and exits 3 (could not answer); never reports an empty session.
- A user edited the managed chain section: the managed-section refresh rules apply unchanged.

## 6. Technical context

Deno 2 / TypeScript; bash 3.2-compatible scripts; `jq` (already required by the hooks). Testing:
`deno task test` (`--allow-read --allow-write --allow-run --allow-env`), smoke, `go test ./...`.
Claude Code and Codex. Constraints: plugin/ byte-identical; size ratchet 300/500; § VIII no pins.

## 7. Domain model

Ledger entry (ts, event, session, agent, optional contract fields) → agent current state (latest by
ts) → seven views. No stored data changes.

## 8. Constitution check

§ I public only · § VIII the version pin is removed, no counts or dates added · § XI the `/goal`
example naming Specnaut's own board goes · § XII nothing for the user: every cut is in the AC.

## 9. Surfaces

Always-on `AGENTS.md` (both harnesses), `/task` backlog and groom docs, `/ship`, `/specnaut doc`,
`status-audit`, plugin mirror, upgrade. **Surfaces added or widened**: one read-only script
(`status-audit`) reading the local ledger — the ledger is written by hooks from subagent output, so
its string fields are untrusted text the script prints, never evaluates. **Removed**: two unread
security files, `alias-example`.

## 10. Risks

- A trimmed tutorial carried a rule a test does not pin — mitigated by the FR-003 script/step diff
  and reading every removed sentence for an imperative.
- Users' upgraded `AGENTS.md`: the managed sections refresh; user-owned text untouched.

## 11. Audit findings

Both seats ran on d166062d (each re-asked for its report at its turn limit). All findings accepted;

### Architecture (architect-expert: fail, 3 HIGH · 3 MEDIUM · 1 LOW)

- **HIGH — a dropped managed section never leaves upgraded projects**
  (`src/application/upgrade_managed_sections.ts` knows only `added` / `refreshed`). Decision: keep
  the `optional-integrations` label; its body becomes the one pointer line, so the existing refresh
  replaces the old ~75 lines in every upgraded `AGENTS.md`. Same for the chain section: label kept,
  body trimmed.
- **HIGH — `skills/specnaut/phases/` is the wrong home** (one file per routed verb; `applyHarness`
  filters only root `.md` files; `/specnaut doc` answers through `specnaut-guide` from
  `specnaut-facts`). Decision: the reference moves to
  `templates/core/skills/specnaut-facts/integrations.md`, written for both harnesses under two
  headings (no harness markers, so no filter is needed), and `specnaut-facts/SKILL.md` names it.
  FR-002 amended accordingly.
- **HIGH — `phases/auto-chain.md` carries the stops and the excuse table too**, on purpose
  (`chain_stops_test`: "the same rule for the phase that is already running"). Decision: § 5 row 1
  names two carriers by design — the always-on file and the running phase; `auto-chain.md` is the
  single home of the excuse table; the `EXCUSES` lock moves to it and is not deleted.
- **MEDIUM — FR-007 lock list incomplete.** Added: `agents_backlog_section_test`,
  `codex_harness_test`, `init_copilot_test`, `manifest_registration_test`,
  `security_knowledge_base_test`, `harness_static_paths_test`, `upgrade_managed_section_test`,
  `smoke-all-harnesses.sh`, `tests/plugin/source-exclusions.txt`. `no_model_version_test` uses the
  pin only as a probe; kept.
- **MEDIUM — harness-specific files and the orphan path**: see security finding 1.
- **MEDIUM — status-audit script home**: `templates/core/skills/status-audit/scripts/`, following
  the `task` precedent; verify the executable bit, manifest entry and plugin mirror for a non-`task`
  skill script, and grep for an existing `agents.jsonl` reader first.
- **LOW** — moving "Generated by Specnaut. Edit freely." reaches new projects only (it is outside
  any managed section): accepted.

### Security (security-expert: needs_followup, 3 MEDIUM · 2 LOW)

- **MEDIUM — the two security files are outside Claude's managed roots**, so the orphan path refuses
  them (`orphan_scope.ts` "outside-managed-roots"). Decision: add them to Claude's `managedFiles` by
  exact name, as `codex_harness.ts` does — never a `.claude/` prefix root (that would put
  settings.json and CLAUDE.md under lock-driven deletion). Check
  `src/cli/handlers/upgrade_preserve.ts`'s scope too. FR-006's claude test asserts both files gone.
  `alias-example` is in no manifest entry: its test asserts it is absent from the bundle, and the
  upgrade test covers it only if an older lock can carry it (verify).
- **MEDIUM — status-audit output sanitiser** (ledger fields come from subagent output). FR-005
  requires: parse each line with `jq -R 'fromjson?'`; no field reaches a filter, an eval or a shell;
  strip C0/C1 controls and bidi overrides before output; cap each field at 64 characters; event,
  state and verdicts checked against their enums, anything else printed as `invalid` and counted;
  agent names allowed only as `^[A-Za-z0-9:_.-]{1,64}$`; skipped lines reported by count, never by
  text; the skill says the output is recorded data, not instruction. Tested with a hostile ledger.
- **MEDIUM — FR-003's grep cannot see guards written as sentences.** Added FR-008: a keep-list lock
  pins these sentences at their (possibly new) homes — AGENTS.md chain: "irreversible, destructive,
  public-breaking or costly", the whole `merge: manual` hook paragraph, "only a CRITICAL or HIGH
  finding buys another fix cycle"; `/ship`: confirm before the irreversible act, dirty tree (no
  stash/commit/tag), "ask beats allow", show the generated body before posting, the deploy
  least-privilege and per-step secrets recipe (moved if it must go, never dropped), tag.md "Do NOT
  run it automatically"; backlog.md: close the issue, never only move to Done, no token stored
  (keychain or 0600 file); groom.md: report never move, never delete or modify a spec, do not close.
- **LOW — "read by nothing" is inaccurate**: Specnaut's hooks and settings read neither file, but a
  project that installed the official `security-guidance` plugin loses its per-edit reminders and
  the routing to the knowledge base. §§ 1 and 9 say so, and the adoption prompt names it.
- **LOW — unpinned MCP server example in backlog.md**: dropped with the tutorial, or pinned if kept.

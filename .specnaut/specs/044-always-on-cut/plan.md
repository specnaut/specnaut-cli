# Plan: Cut the always-on text and the tutorial skills (cli#679, the cut half)

**Branch**: `044-always-on-cut` | **Date**: 2026-10-30 | **Backlog item**:
[specnaut-cli#679 — Slim the bundled skills and always-on text; enforce must-hold rules with hooks](https://github.com/specnaut/specnaut-cli/issues/679),
child of epic #674. The enforce half landed in spec 036; this is the cut half that waited on an
eval. The eval was dropped (Kevin, 2026-10-29): cuts land on a green suite, no content guard
weakened, bytes reported before and after — always-on bytes for both harnesses.

**Full plan** — the change deletes files in users' projects on upgrade (step 4b: files written or
deleted in someone else's project). It reuses the lock-driven orphan path, as cli#678 did.

## 1. Why this exists

Always-on context in a scaffolded project: `templates/core/root/AGENTS.md` is 12,972 B, of which the
`Optional integrations` tour (~75 lines, reference, tells the agent nothing to do) and the chain
section's five-row excuse catalogue (written for weaker models) are the bulk. It also pins a harness
version ("Requires Claude Code v2.1.139+", § VIII) and places "Generated by Specnaut. Edit freely."
mid-file, above six managed sections. `/task backlog.md` (17,690 B), `groom.md` (12,844 B) and
`/ship` (6,009 + 10,227 + 2,681 B) carry tutorial prose around their command tables. `alias-example`
is not installed and nothing reads `alias_of`; `claude-security-guidance.md` and
`security-patterns.yaml` are read by nothing (spec 036 decided: remove). `status-audit` asks the
model to derive seven views from JSONL by hand.

## 2. User scenarios

### US1 — a session starts in a scaffolded project (P1)

**Given** a project scaffolded or upgraded with this bundle **When** a Claude Code or Codex session
starts **Then** the always-on `AGENTS.md` carries the rules — constitution pointer first, the two
stops, invoke the next phase yourself, only CRITICAL/HIGH buys a cycle, the `merge: manual` hook —
and one pointer line to where the optional integrations are documented.

### US2 — the user asks for a session health report (P2)

**Given** `.specnaut/logs/agents.jsonl` **When** the user runs `/status-audit` **Then** a bundled
`jq` script computes the seven views and the skill presents them; the same on Codex (the ledger is
registered there since spec 036).

### US3 — a project upgrades (P1)

**Given** a project scaffolded with `alias-example` and the two security-guidance files **When**
`specnaut upgrade` runs **Then** they are removed through the orphan path, a customised one kept and
warned until `--force`; the trimmed managed sections replace the old ones.

### Edge cases

- A ledger line that is not JSON: skipped and counted, as today.
- `jq` absent: the script says so and exits 3 (could not answer); never reports an empty session.
- A user edited the managed chain section: the managed-section refresh rules apply unchanged.

## 3. Requirements

- **FR-001**: `AGENTS.md` (template): the chain section keeps every rule and drops the excuse table;
  `Optional integrations` leaves the always-on file for an on-demand doc (below) with one pointer
  line; no harness version anywhere in it; "Generated by Specnaut. Edit freely." moves to the end or
  goes; the constitution pointer stays first (#684/#685 guard).
- **FR-002**: the integrations text moves to `templates/core/skills/specnaut/phases/integrations.md`
  (read by `/specnaut doc` on request), harness-filtered as today, without the version pin and
  without the `/goal` example that names Specnaut's own board (closes cli#687's item).
- **FR-003**: `/task backlog.md`, `/task groom.md` and `/ship` (SKILL.md + phases) are trimmed to
  command tables and steps: tutorial prose goes; scripts, steps and step order unchanged — verified
  by a diff of every script invocation and step heading before/after (search:
  `grep -nE
  '\.sh|^#+ |^[0-9]+\.'`).
- **FR-004**: `alias-example` and `claude-security-guidance.md` / `security-patterns.yaml` are
  removed from the bundle, manifest, plugin mirror and coverage lists.
- **FR-005**: `status-audit` becomes `templates/core/skills/status-audit/scripts/status-audit.jq`
  (or a `.sh` wrapper around `jq`) plus a short skill; exit codes 0 / 2 usage / 3 could not answer;
  the seven views keep their names and meaning; works on both harnesses.
- **FR-006**: upgrade prunes the retired files through the lock-driven orphan path only; an
  integration test pins it on claude and codex.
- **FR-007**: every lock that pinned moved text pins it at its new home (status_audit_skill_test,
  agents_managed_section_test, chain_stops_test, init/init_codex, plugin_sync, plugin_coverage,
  smoke-features, response_style / constitution_first where they read AGENTS.md).

## 6. Technical context

Deno 2 / TypeScript; bash 3.2-compatible scripts; `jq` (already required by the hooks). Testing:
`deno task test` (`--allow-read --allow-write --allow-run --allow-env`), smoke, `go test ./...`.
Claude Code and Codex. Constraints: plugin/ byte-identical; size ratchet 300/500; § VIII no pins.

## 7. Domain model

Ledger entry (ts, event, session, agent, optional contract fields) → agent current state (latest by
ts) → seven views. No stored data changes.

## 8. Constitution check

§ I public only · § VIII the version pin is removed, no counts or dates added · § XI the `/goal`
example naming Specnaut's own board goes · § XII nothing for the user: every cut is in the AC.

## 9. Surfaces

Always-on `AGENTS.md` (both harnesses), `/task` backlog and groom docs, `/ship`, `/specnaut doc`,
`status-audit`, plugin mirror, upgrade. **Surfaces added or widened**: one read-only script
(`status-audit`) reading the local ledger — the ledger is written by hooks from subagent output, so
its string fields are untrusted text the script prints, never evaluates. **Removed**: two unread
security files, `alias-example`.

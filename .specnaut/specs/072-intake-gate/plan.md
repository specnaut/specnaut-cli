# Plan: unfinished landings and closeouts block new work (cli#760)

Linked item: specnaut-cli#760 "Block new work until verified merges and post-merge closeout finish",
https://github.com/specnaut/specnaut-cli/issues/760. Branch `feat/760-closeout-gate`, base
`origin/main` @ `5aea8dad`.

**Full plan (step 4b).** It crosses three threshold lines:

- **Files written or deleted in someone else's project:** a resumed closeout pushes a removal commit
  to the base.
- **A new place that accepts untrusted input:** the published base's `.specnaut/feature.json`, which
  whoever merged wrote, now drives a tracker close and a removal pushed to the base.
- **Changes the instructions that decide when an agent may start work.**

This is revision 3. § 4 records every finding from both seats over two rounds, and what was done
with each.

## 1. Task and out of scope

**Outcome.** In a scaffolded project, `/task` starts no unrelated work, and lands no other branch,
while an earlier landing is unsettled. `/task resume <n>` finishes that landing's closeout from its
first unfinished step, and running it again does no harm. When a step fails, it is named, intake
stays blocked, and the item stays open.

A landing is unsettled when either of these holds:

- **(P) push pending.** `refs/heads/<base>` has commits that `refs/remotes/origin/<base>` does not.
- **(C) closeout pending.** The published base tracks `.specnaut/feature.json` with a numeric
  `linked_issue`. On every backend, the last step of a closeout that has an issue removes that file
  (FR-6), so while the file is there, `merge-close.md` has not finished. This holds for a direct
  merge, a merged PR and a `--no-close` slice alike. A marker whose `linked_issue` is `null` has no
  closeout and never blocks.

**Out of scope:**

- **Worktree removal.** After a compaction, nothing records which worktrees the run owns
  (`templates/harness-specific/codex/session-lifecycle.md`).
- **A branch prune in resume.** `land-feature.sh`'s `git branch -d` stays the only place that does
  it.
- **The Go port (cli#660).**
- **Groom and `next`.** Neither starts work.

**New helper vs reuse.**

- **(a) Inventory.** `wip-audit.sh` already resolves the base, reads `origin/<base>..<base>`, reads
  `feature.json` from a ref, and has `unread` (exit 3). `remove-spec.sh`, `epic-status.sh` and
  `cascade-check.sh` are extended where they live.
- **(b) Recurrence.** This stop has been written in prose twice before, in #727 and #729, and this
  is the third time. Separately, the gate will not fit inside `wip-audit.sh`'s 200-line target.
- **(c) Outcome.** **Extend at the owner, with the base resolution extracted.** `_base_refs.sh` is
  shared, and `_intake_gate.sh` is sourced by `wip-audit.sh --gate`. They take only numbers and
  validated paths, and keep their exit codes. The one new exit is 4 (blocked).

### Constitution principles this could break

- **No logic in prose:** each rule is decided once, in the place the table names.
- **Fail closed:** only `gate clear` on exit 0 lets a caller proceed. `PENDING push` is never
  exempt. A fence is crossed only with a yes, and only for that run.
- **Untrusted text is data:** `feature.json` is read only by the gate, and only through regexes on
  digits and paths. No subject, branch or file text reaches a comment.
- **Consumer agnosticism:** the fixtures are synthetic.
- **Size discipline:** FR-15.

### Surfaces

- **Scripts:**
  - `wip-audit.sh` gains a dispatcher, plus `_base_refs.sh` and `_intake_gate.sh`;
  - `epic-status.sh --landed`;
  - `remove-spec.sh --marker-only`.
- **Phase docs:** `plan.md`, `auto-chain.md`, `implement.md`, `merge.md` (steps 0–5),
  `merge-close.md` (steps 2 and 4, plus § Re-entry), `resume.md` and `epic-commits.md`.
- **Mirrors:** the `plugin/` copies, the plan golden file and the template bundle.

**Surfaces added or widened:**

- Resume now closes, comments, moves items and pushes a removal commit to the base. It is driven by
  the gate's validated line and corroborated by a commit on the published base that names the item,
  and by `cascade-check`.
- Merge refuses to land over another item's unsettled closeout.
- **Accepted residuals** (the "mistakes, not adversaries" model of `resume.md` § 3):
  - A crafted landing can forge the FENCED anchor, a corroborating subject, or a `PARTIAL` /
    `INVALID` marker that blocks intake.
  - A close that fails after its comment was posted posts that comment again on a re-run.
  - `--own` trusts the board's parent link.

## 5. Open questions

None for the user. **The per-PR block is not a new product decision.** #760 says: "Finish the
verified landing and closeout before taking unrelated work", for direct merges **and merged pull
requests**. It is reported under § 6 and in the Agent adoption section.

## 6. Decided without asking

- `--no-close` slices block unrelated work, because #760 asks for that. They are marked `partial`,
  so they are never closed by mistake.
- On the `--pr` flow, every merged PR blocks intake until `/task resume <n>` closes it out. This is
  the issue's own requirement.
- After an upgrade, a stale `feature.json` on the base blocks once.
- No worktree or branch prune beyond `land-feature.sh`.

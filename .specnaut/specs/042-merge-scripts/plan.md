# Brief — Merge, close and fixup mechanics as scripts

Backlog item: specnaut-cli#677 "Move merge, close and fixup mechanics from phase prose into scripts"
(https://github.com/specnaut/specnaut-cli/issues/677), child of epic specnaut-cli#674. Branch:
`042-merge-scripts`. Lands on a green suite, no content guard weakened, bytes reported.

## 1. Task and out of scope

**Task.** The deterministic git and board steps of `merge`, `merge-close` and `epic-fixups` move
into four bundled scripts with documented exit codes; the three docs shrink to the judgement the
scripts cannot make, and invoke them.

| Script                      | Does                                                                                                                                                                                                                                                                                                     | Exit codes                                                                                                                                                                               |
| :-------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `land-feature.sh [<base>]`  | merge steps 2–3 and 6–10: clean tree, fetch, branch contains `origin/<base>`, checkout base, `merge --ff-only`, push, `branch -d`, verify `HEAD` is the base; prints `LANDED <base> <first>..<last>`                                                                                                     | 0 landed and pushed · 2 usage · 3 base unknown · 4 dirty tree · 5 behind the base · 6 not a fast-forward · 7 push rejected (merge left local, nothing retried) · 8 branch delete refused |
| `fold-fixups.sh [<base>]`   | captures the diff, `rebase --autosquash --keep-base`, then the three checks: tree unchanged, worktree clean, one commit per child in order (through `epic-status.sh`)                                                                                                                                    | 0 folded · 2 usage · 3 base unknown · 10 tree moved · 11 worktree not clean · 12 not one commit per child · 13 rebase stopped on a conflict                                              |
| `epic-status.sh [<base>]`   | reads the branch's commits: `EPIC #<n>`, one `CHILD T<NN> #<child> <sha>` per child, `FIXUP <sha>` per surviving fixup; checks ordinals dense from 1, each child once, subject and ordinal agree                                                                                                         | 0 consistent · 2 usage · 3 base unknown · 12 inconsistent (named on stderr) · 14 not an epic branch                                                                                      |
| `close-shipped.sh <issue>…` | after the product-owner closed them: per issue, refuses an issue still open, else `move.sh <n> Done`; then removes the spec directory under its five conditions, in its own commit, pushed; then `sweep-closed.sh --passes 2` and one `move-batch.sh Done` for every `DRIFTED`; prints one line per item | 0 all done · 2 usage · 20 an issue was still open (its card left alone) · 21 a card move failed · 22 spec removal skipped (reason printed; not a failure of the close)                   |

What stays prose, because it is judgement: squash grouping (`merge-squash.md`), the `--pr` path,
attributing a fixup to its child, the product-owner's close and comment, the report.

**Out of scope.** The `/board` and `/ship` scripts; slimming other phase docs; the Go port.

## 2. Guardrails

| New helpers? (a) inventoried: `base-branch.sh`, `merge-mode.sh`, `run-gate.sh`, `cascade-check.sh`, `move.sh`, `move-batch.sh`, `sweep-closed.sh`; (b) recurrence: every merge since spec 033 re-derives these steps by hand, and #552, #557, #560, #587 each repaired one; (c) outcome | **add** four scripts that call the existing helpers and take data only (a base name, issue numbers) | a script that takes a command to run                                       |

Constitution: none of the four principles is at risk — this is tooling around the phases. Surfaces
added or widened: **one** — a script that pushes to the base branch, which is an agent instruction
surface; `guard-merge.sh` must gate it under `merge: manual` exactly as it gates `git push`. The
scripts are bash only, like `base-branch.sh`, `merge-mode.sh` and `size-ratchet.sh` that the merge
phase already calls: they drive `git`, which ships Git Bash on Windows; a PowerShell twin would be a
second implementation of the same git sequence (the issue's AC asks for twins — the architecture
seat rules).

## 4. Audit findings — and the design they produced

**The scripts, as built** (supersedes § 1's table where they differ):

| Script                            | Home, category                                                                | Does                                                                                                                                                                                                                                                                                                                                  |
| :-------------------------------- | :---------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `land-feature.sh`                 | `specnaut/scripts/bash/`, spec-root                                           | no argument — the base is `base-branch.sh`'s; pushes `HEAD:refs/heads/<base>` with `--no-follow-tags`                                                                                                                                                                                                                                 |
| `fold-fixups.sh [--verify <pre>]` | same                                                                          | prints `PRE <sha>` first; the "tree did not move" check compares `<pre>^{tree}` with `HEAD^{tree}`; after a conflict, `--verify <pre>` runs the three checks against the recorded tree                                                                                                                                                |
| `epic-status.sh`                  | same                                                                          | no argument; reads subjects only, anchored regex, prints digits and hex shas only                                                                                                                                                                                                                                                     |
| `remove-spec.sh`                  | same                                                                          | the five conditions, then validates `feature_directory` (relative, no `..`, not a link, resolves directly under the specs root, basename equals the branch that landed); `git rm -r -- <dir> .specnaut/feature.json`; every staged path must be a deletion under it; explicit-refspec push, `--no-follow-tags`                        |
| `close-shipped.sh <issue>…`       | `task/scripts/<backend>/`, backlog-script, one per backend, one exit contract | after the product-owner's close: github and gitlab confirm each issue is closed (`cascade-check.sh` exit 12 only), move it Done, then sweep and move every `DRIFTED` (`move-batch.sh` on github, `move.sh` per item on gitlab); local and cloud: `move.sh <n> Done` is the close itself; issue numbers must match `^[1-9][0-9]{0,9}$` |

Exit codes: 0 success · 2 usage · 3 could not answer, everywhere; each script's own range above.
`fold-fixups.sh` passes `epic-status.sh`'s 12 and 14 through and maps every other inner code.

### Architecture (`architect-expert`, 2026-10-29): fail, 3 HIGH · 2 MEDIUM · 2 LOW — all accepted

| Finding                                                                                 | Decision                                                                                                                                                                                                                                                                                                                       |
| :-------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HIGH — the spec-removal push inside `close-shipped.sh` is invisible to `guard-merge.sh` | It moves to `remove-spec.sh`, and every script that pushes to the base is listed in one file, `merge-commands.txt`, read through the same basename matcher as `release-commands.txt` — `listed()` moves from `guard-release.sh` into a shared `_listed.sh`                                                                     |
| HIGH — `close-shipped.sh` assumed GitHub and inverted the local close                   | One copy per backend under `task/scripts/<backend>/`, the installer picks it, no backend switch                                                                                                                                                                                                                                |
| HIGH — after a conflict the tree check compared the result with itself                  | `PRE <sha>` + tree ids + `--verify <pre>`                                                                                                                                                                                                                                                                                      |
| MEDIUM — exit tables incomplete across calls                                            | Passthrough of 12 and 14 stated, shared 0 / 2 / 3                                                                                                                                                                                                                                                                              |
| MEDIUM — nine more files pin the moved text                                             | Each assertion re-pointed at the rule's new home (`smoke-task.sh`, `addendum_audit.ts`, `skill_doc_renames.ts` and their tests, `cascade_check_fails_open_test`, `create_new_feature_number_reuse_test`, `propagate_parent_open_test`, `backlog_reference_contract_test`, `phase_addenda_test`)                                |
| LOW — format defined in a doc, parsed in a script                                       | A test feeds `epic-commits.md`'s own example through `epic-status.sh`; `epic-loop.md` resumes from its `CHILD` lines                                                                                                                                                                                                           |
| LOW — editing `guard-merge.sh` changes the hash Codex users trusted                     | `SHA256SUMS` and the pinned hash regenerated; the adoption note says to re-trust through `/hooks`                                                                                                                                                                                                                              |
| Fork (a) — bash only vs the AC's PowerShell twins                                       | **Bash only.** The merge phase already calls bash-only scripts (`base-branch.sh`, `merge-mode.sh`, `size-ratchet.sh`), both harnesses run the hooks through bash, every backlog script is bash, and a twin would be a second implementation of a guarded git sequence the hook cannot read. The product-owner amends #677's AC |

### Security (`security-expert`, 2026-10-29): fail, 2 HIGH · 2 MEDIUM · 3 LOW — accepted, two to the backlog

| Finding                                                                                                                                          | Decision                                                                                                                                                                      |
| :----------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HIGH — a second push to the base, ungated                                                                                                        | `remove-spec.sh` is in `merge-commands.txt`; surfaces added: **two** pushing scripts                                                                                          |
| HIGH — `feature_directory` reaches `git rm -r` + push unvalidated                                                                                | The validator in `remove-spec.sh` (table above)                                                                                                                               |
| MEDIUM — the hook's normaliser misses `timeout`, `xargs`, `caffeinate`, `find -exec`, `source` (verified letting `git push origin main` through) | Fixed here, in `_simple.sh`: those wrappers are skipped, `source` / `.` read like `bash <script>`, `find -exec` read as its own segment — it guards this change's own surface |
| MEDIUM — a scripted push can publish tags                                                                                                        | Both pushing scripts use `--no-follow-tags` and an explicit refspec; a test sets `push.followTags=true`                                                                       |
| LOW — the `<base>` override                                                                                                                      | Dropped; tests set `origin/HEAD`                                                                                                                                              |
| LOW — child ids and issue numbers unvalidated                                                                                                    | Subjects only, anchored, digits only; issue-number regex                                                                                                                      |
| LOW — the mode is read for the session's project, not a `cd` target's                                                                            | Backlog: a hook limit that predates this change                                                                                                                               |
| Note — `case ${W[0]}` crashes (fails closed) on an empty segment                                                                                 | Fixed in passing: `${W[0]:-}`                                                                                                                                                 |
